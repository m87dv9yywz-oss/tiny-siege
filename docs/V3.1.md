# Tiny Siege 3.1 — Sunflower & Grove

This feature branch builds on the deployed, tagged v3.0.0 release. Phaser 4.2.1, Vite 8.3.4, GitHub Pages `/tiny-siege/`, the existing Firebase project and the free Spark plan remain in place. No paid products or additional infrastructure are enabled.

## Flow and interface

The entire battle uses a bounded `100dvh` layout with safe-area padding, a visible top bar, and no page scrolling. Battle controls never dismiss the selected upgrade panel. Empty battlefield/background taps still close it while keeping the tower's range selected. Tap the same tower again or choose Upgrades to reopen it. Menu explicitly offers Keep playing or abandon to Main menu; abandoning checkpoints earned XP, ends the run and clears combat state. It does not award victory Crowns.

The compact home screen gives four adventures large numbered tiles, explicit NEW versus earned-star labels, a recommended first uncleared adventure and a separate fully unlocked Classic option. Hero management and parent sign-in remain optional. Kingdom collection uses one tower at a time with six illustrated tabs rather than a stack of all towers.

The left upgrade panel shows artwork, stats, target priority, three illustrated path cards, purchased-tier markers, prices/locks and selling together. In portrait it is a compact sheet; it does not hide battle controls or the shop. Full tree or each path's information button opens a three-tier blueprint with real costs, exact incremental damage/range/attack-rate/status changes and future attack descriptions. One path tab at a time makes all nine upgrades accessible. Preview keeps at most one legal Tier-1 crosspath; locked paths can be planned for a separate tower. Battle simulation pauses while reading and restores the previous pause state. Escape returns safely.

Before a class's first appearance on each campaign, starting its wave shows a short ability/counter card. Ready starts the wave; Prepare my defense returns without spawning or consuming the wave. No automatic mid-combat interruptions. Subsequent appearances do not repeat the card.

## New content and visual progression

Sunflower Gardens: 18 sunny waves, a new shared spline, sunflower scenery, mixed shields/healers/splitters and final armored captains. First clear awards 140 Crowns; repeat clears 50. It is intermediate difficulty with a developed hero. Classic and the original three progression maps are retained.

Grove: 115 battle gold, 90 permanent Crowns to unlock, then the existing per-path 180/500 XP unlock costs. Gold upgrade prices are 140/330/820. Same 3-1-0 rule and 70% invested sell value.

- Thorn Sentinel: ruby thorns become piercing bramble spears and a four-shot living fortress. Strong physical armor damage.
- Seedburst Orchard: splash pods gain bounded bounces, then five-enemy chains with seed explosions at the first impact. No recursive splitting or extra kill rewards.
- Elderwood Guardian: slowing leaves gain temporary damage/slow root patches, then wide patches and periodic rooting pulses. Boss resistance and freeze immunity prevent permanent root locks.

All six classes visibly change on every purchased tier: path ornaments and banners, tier-specific textures, projectile colour/size/trail recipes, heavier arrowheads and shells, crystalline frost, flame comets and stronger lightning. Tier-1 portraits also change, and each ultimate has distinct original procedural and SVG artwork. Reduced effects and existing bounded effect/particle/zone limits are preserved. The unchanged original custom home-screen icon remains configured.

## Save migration and release gate

Profile schema 2 retains the same 13 top-level fields, adds `towerXP.grove` and `unlockedUpgrades.grove`, and recognizes `garden` in completed maps/stars. Cloud wire XP is twelve flat integer Earned/Spent fields. Existing local and cloud schema-1 saves migrate in memory with zero Grove XP, Tier-1 path access and no free tower unlock, without changing Crowns, old XP, ledgers, stats, stars or pending operations. New clients write schema 2 using transactions and fresh server timestamps. Older clients cannot downgrade a cloud schema-2 document. Original guest saves remain exportable; imports and cross-device purchases retain existing accounting/idempotency protections.

The rules continue to require parent UID ownership, exact schemas, enumerated keys, bounded counters/ledgers, validated creates AND updates and default denial elsewhere. Rules accept full legacy v3 documents and new Grove/garden documents, with a downgrade guard on updates. Emulator tests cover both complete schemas at maximum bounds, malicious Grove fields and a live legacy-to-new migration.

**Do not merge/deploy this release until an authenticated administrator publishes the exact tested `firestore.rules` from this PR and verifies the active contents in `tiny-siege-game` / `(default)` Firestore.** The deployed v3 rules only accept schema 1. This workspace has no Firebase administration identity; the existing v3 deployment confirmation applies to the old rules, not this change. Rules can be published first because they retain schema-1 compatibility. Only rules should change; Spark, data and Auth providers must remain unchanged. After that gate, the normal PR validation/main Pages workflow builds, deploys and verifies the public game. No further project setup is needed.

## Validation and balance

`npm test` covers all old combat/progression behavior plus Grove specializations, visual recipes, accurate future trees, introduction schedules and lossless local/wire migration. Browser tests retain original interactions and add seven-viewport no-scroll menus/panels/collection/trees, panel persistence on controls, leave/cancel flows, introduction readiness and all 18 future trees on small portrait/landscape screens. Auth/Firestore checks exercise isolation, malformed writes, both schema bounds and downgrade rejection; the multi-browser cloud scenario also syncs Grove XP/path unlocks, garden stars and duplicate Grove purchases.

`node scripts/v3-balance-report.js` records 15 legal earned-gold campaigns: six existing progression routes, then each Grove path's introductory, earned Tier-2 and earned ultimate garden runs. All win; first three waves retain 20 lives. Beginner ends at 20, first earned-Tier-2 Amber at 11, Moon and developed Gardens at 20. These establish viable strategies, not that every novice or standalone tower wins. Higher Grove unlocks use actual XP from previous participation and a tower bought using earned Crowns. Detailed wave gold/spending, lives, escapes, tower paths, times and reward state are in `docs/v3-balance-results.json`.

Production smoke uses only shipped UI, including legal touch placement and a paid upgrade, panel dismissal/reopening, leave-to-menu, a real Beginner wave XP checkpoint and reload. No physical iOS Safari or real Google consent is implied by Chromium/emulator testing. Advanced parent backup/sync-review pages may scroll for long save details; core play, home/collection and tree screens fit the tested viewports.
