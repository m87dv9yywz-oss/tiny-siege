# Tiny Siege v4 — Heroes & Kingdom Expansion

The recoverable production release is `v3.1.0`, commit `ea71c7a`. V4 is developed on `feature/tiny-siege-v4-heroes-expansion` and does not include infrastructure PR#8. Phaser4.2.1, Vite8.3.4, Canvas and GitHub Pages `/tiny-siege/` remain unchanged. Firebase uses the existing STANDARD default database in `tiny-siege-game`, Spark, Google only, with no billing, Functions or paid products.

## Playing

Measured viewport fitting replaces CSS container-height assumptions, including visualViewport/browser-toolbar changes. The map fits wholly in its frame, preserves3:2 proportions and stays directly below the compact HUD. Phone portrait and landscape switch on the same page; native pointer events derive world coordinates from the current canvas rectangle. One tap on existing artwork opens the left upgrade panel, switches directly between towers and highlights range. Empty battlefield closes it. Portrait uses a left-anchored compact sheet with space reserved for controls; the shop remains available. Full-tree reading restores the previous pause state.

Each adventure offers just Easy(20), Medium(40), Hard(100). Classic preserves original20-wave play, without permanent rewards. Easy introduces mechanics gradually and uses modest4800-health final bosses. Medium adds mixed formations and a second boss milestone. Hard has five boss milestones and stronger late armor/shields, bounded linear enemy growth and finite summons. Clear rewards are100/180/350 Crowns initially, then15/25/40 for up to five repeats per map/difficulty; thereafter XP remains available but Crowns stop. Existing stars/completion remain, and legacy clears already count as Easy's first reward, preventing duplicate first-clear rewards.

## Animal friends and relics

Exactly one equipped animal enters each adventure. Ember/Fire Dragon and Stripe/Tiger are free starters; Rex/Dinosaur costs40 earned Crowns. Heroes attack automatically, move to valid destinations after a tap, show attack/support ranges, and have active abilities: Dragonfire, Thunder Stomp and Pounce Rush. Dragon empowers nearby Fire damage/burn; Dinosaur empowers Cannon armor damage; Tiger improves Archer speed. Ground heroes route around obstacles; Dragon flies. Bosses resist stuns/pushes and have control cooldowns. Permanent hero XP grants bounded levels1–10 and small damage bonuses. All clocks use simulation delta and honor pause/speed.

Six original illustrated relics unlock from completed adventures/stars: Golden Acorn(+25 starting gold), Kindred Banner(+20% hero buff range), Guardian Shell(+2 lives), Crystal Lens(+5% tower range), Warmheart Charm(+10% hero damage), Steadfast Crown(10% faster abilities). Equip at most two distinct earned relics. No purchases or unlimited stacks.

## Continue battle

The last reliable between-wave checkpoint retains map/difficulty, wave, lives, gold, tower positions/paths/targeting/investment/attack counters, hero position/cooldowns, relics, participation metrics and the original reward run ID/granted totals. Wave start saves the prepared defense. Clear saves rewards and the next checkpoint. Visibility loss pauses; page closure retains the checkpoint. Save & main menu offers Continue Battle; Abandon clears it. Restoration starts paused and validates all state/ownership/placement before applying it. An interrupted wave restarts from its pre-wave checkpoint: partial kills/gold are not retained, and cumulative reward counters prevent duplicate XP. Mid-wave snapshots are deliberately unsupported.

Backups retain guest/family profiles plus checkpoints and durable receipts. Import creates independent copies, validates checkpoints and keeps source data. Guest-to-cloud import carries its checkpoint; merging an existing profile preserves its cloud checkpoint, while explicitly reviewed replacement uses the guest checkpoint and checks both permanent and battle revisions.

## Cloud schema and migration

Legacy schema1(five towers) and2(Grove/garden) are validated/migrated losslessly to local schema3, retaining Crowns, all earned/spent XP, path unlocks, stars, stats, settings and old receipt IDs. New tower progress starts at0, paths at Tier1, without free tower unlocks. The original device save key/version remain, unreadable/future formats remain untouched, and stale local tabs stop before overwriting changed storage.

New cloud root: `users/{uid}/kingdoms/{profileId}`. Its bounded core holds nickname/avatar/Crowns, counters/settings/achievements and migration status. Known component documents hold eight towers, three heroes, six maps/difficulty claims and relic loadout. A battle has a bounded core, up to80 separate placement documents and eight metric documents. New operation receipts are independent immutable documents, looked up only for queued operations, rather than appended to a growing profile. Local recent ledger is bounded128 IDs; durable device receipts and immutable cloud receipts prevent ancient replay. One-time legacy history is bounded194KB in a separate archive; it never grows.

Migration writes components atomically as `migrating`, seeds durable guest receipts in bounded batches, reads/validates assembled server state, then activates. The legacy profile is never deleted/replaced by migration. Old clients cannot write the legacy profile after migration starts. Transactions replay intent on newest permanent state, spend actual balances and deduplicate reward IDs. Pending operations survive offline/reconnect and ongoing sync. Stale battle revision conflicts keep the local checkpoint and offer backed-up cloud recovery. Deleted profiles leave a tombstone so old tabs/legacy copies cannot resurrect them. Only an explicit owner deletion removes the legacy document.

Owner UID comes from Google Auth; family profile selection is not authentication. Rules default deny outside these paths, bound/type every document, validate creates and updates, keep receipts/history immutable, and deny guest/other-parent access. Structured placement documents enforce legal paths/investment; client validation also enforces map geometry, collision and owned unlocks. Game outcomes remain client-trusted, as appropriate to an offline family game; this is not an anti-cheat service.
